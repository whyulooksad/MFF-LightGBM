# 项目结构

项目只有两条正式通道：开发者负责准备数据、训练、验证和发布；用户系统只接收 PCAP 并加载已发布模型检测。旧源码和旧模型全部位于 `legacy/`，正式源码不导入它们。

```text
E:\Work\ccb
├─ developer/                       开发者制模与升级
│  ├─ pipeline.py                   离线完整流水线
│  ├─ data_prepare/                 清单、标签、分组划分、批量提取
│  ├─ representation/               RTD 继续预训练、LoRA 八分类、CLS
│  ├─ detector/                     SupCon-AE、LightGBM、PCA 对照
│  ├─ evaluation/                   独立测试、消融、资源和版本比较
│  └─ release/                      候选包校验与不可变发布
├─ user_app/                        用户检测系统（不含训练入口）
│  ├─ inference/
│  │  ├─ pcap_reader.py             Scapy 解码 PCAP/PCAPNG/链路/IP
│  │  ├─ tcp_reassembly.py          TCP sequence 重组、去重、缺口隔离
│  │  ├─ tls_parser.py              TLS record/Hello/Certificate 解析
│  │  ├─ x509_parser.py             cryptography X.509 DER 解析
│  │  ├─ extract_flow_features.py   唯一的流与 80 维特征实现
│  │  ├─ serialize_flow.py          结构化事件转 DeBERTa 文本
│  │  ├─ semantic_encoder.py        Encoder + LoRA 与 CLS
│  │  ├─ supcon_reducer.py          SupCon-AE 推理
│  │  ├─ lightgbm_detector.py       LightGBM 推理
│  │  ├─ model_loader.py            生产模型与特征契约校验
│  │  └─ pipeline.py                PCAP 到八分类结果
│  ├─ backend/                       FastAPI、任务、SQLite、结果读取
│  └─ frontend/                      上传、结果、告警、TLS 页面
├─ data/
│  ├─ developer/
│  │  ├─ datasets/source/            官网原件及原样解压内容
│  │  ├─ datasets/manifests/         哈希、标签、group_id、split
│  │  ├─ datasets/prepared/          train/validation/test PCAP 硬链接
│  │  └─ workspace/                  可重新生成的语料、特征和评估
│  └─ runtime/                       用户上传、任务产物和服务状态
├─ models/
│  ├─ base/                          原始基础模型
│  ├─ experiments/                   开发者候选模型
│  └─ production/                    用户系统唯一可加载的位置
├─ tests/                            单元、开发、后端和集成测试
└─ legacy/                           旧源码、旧数据产物和旧模型，仅追溯
```

依赖方向是 `developer → user_app.inference`。反向导入由架构测试禁止。离线与在线共同调用唯一的 `extract_pcap()`，因此不存在训练一套、上传时再实现另一套的问题。

旧的逐流前 N 包截断器已经归档。新解析器必须先看到完整 sequence、重传和 TLS record 边界，因此不会在 TCP 重组前破坏抓包。
