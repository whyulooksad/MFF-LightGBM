# 系统复习文档（当前实现）

## 一句话目标

用户上传 PCAP/PCAPNG；系统不解密正文，而是根据流量行为、可见 TLS 握手和证书元数据，把双向流分成正常、广告软件、三种 DNS 隧道、勒索软件、恐吓软件、短信恶意软件八类。

## 推荐阅读顺序

1. `README.md`：先知道目标、当前状态和两条通道。
2. `docs/项目结构.md`：建立目录地图。
3. `user_app/inference/contract.py`：标签与 80 维特征契约。
4. `pcap_reader.py → tcp_reassembly.py → tls_parser.py → x509_parser.py`：理解原始抓包如何变成可信字段。
5. `extract_flow_features.py → serialize_flow.py`：理解双向流、数值特征和结构化文本。
6. `semantic_encoder.py → supcon_reducer.py → lightgbm_detector.py`：理解 CLS、降维、融合和分类。
7. `user_app/inference/pipeline.py`：把用户推理全链串起来。
8. `developer/data_prepare → representation → detector → evaluation → release`：最后看如何重训和升级。
9. `user_app/backend → frontend`：看任务 API 与用户页面，不要用前端反推模型流程。

## 数据到预测

```text
PCAP/PCAPNG
→ Scapy 识别文件、接口、链路层、VLAN、IPv4/IPv6
→ IP 分片重组
→ 规范化双向五元组
→ 根据 SYN 确定客户端；无 SYN 时明确标记“首个观测包方向”
→ TCP sequence 排序、重传/重叠去重、捕获缺口隔离
→ TLS record 与 handshake 消息解析
→ ClientHello/ServerHello、SNI、ALPN、版本、cipher、extensions
→ 可见 Certificate 的 DER 交给 cryptography.x509
→ 80 维数值特征 + connection/TLS/X.509 JSON
→ JSON 序列化成短结构化事件文本
→ DeBERTa-v3-base 最后一层第 0 个 token（CLS）得到 768 维
→ SupCon-AE 压到 64 维
→ 64 维语义 + 80 维数值
→ LightGBM 八分类概率
```

## 为什么不用生成式模型

这里的目标是把短而结构稳定的事件序列编码成固定向量，不是生成文字。编码器只需一次前向计算，CLS 天然适合做样本级表示；生成式模型的自回归输出、解码成本和自由文本不为这个任务增加必要能力。DeBERTa-v3-base 是当时在效果、显存和 768 维生态之间的工程选择，不是理论上唯一正确的模型；新实验仍必须和更小编码器、纯手工特征及其他基线比较。

CLS 可以理解为整段输入的“摘要位置”。模型输出形状是 `[batch, sequence_length, 768]`，取 `[:, 0, :]` 后，每条流得到一个 768 维向量。

## TLS、X.509 与可见性

TLS 是加密传输协议。ClientHello 通常能看到客户端提供的 SNI、ALPN、版本、密码套件和扩展；ServerHello 能看到最终协商参数。TLS 1.3 在 ServerHello 后会加密大部分握手，没密钥时看不到 Certificate 是正常现象，系统会标为 `encrypted_or_not_captured_tls13`，不会伪造证书。

X.509 是证书的数据模型；ASN.1 是描述其结构的语言，DER 是常见二进制编码。当前代码不手搓完整 ASN.1，而是把握手中取得的 DER 交给 `cryptography.x509.load_der_x509_certificate()`，读取 Subject、CN、SAN、Issuer、序列号、有效期、签名算法、公钥类型/长度和 SHA-256 指纹。

## 80 维特征的口径

- 包长与字节数统一使用 IP packet length，不混用二层 frame 长度。
- header length 是实际 IP 扩展/选项加 TCP/UDP 头，不写死 IPv4 40 字节。
- transport payload 均值只统计传输层载荷。
- handshake duration 是 SYN 到完成三次握手 ACK，不等于整条流持续时间。
- active 最后一段会结算；idle 只有真正存在超过 5 秒间隔时才有值。
- subflow 在相邻包间隔超过 1 秒时切分，字段表示每个 subflow 的平均包数/字节数。
- 窗口行为只看同一 PCAP 中当前时刻之前 60 秒，避免使用未来信息。
- 证书和 CN 字段只来自真实叶证书；SNI 不冒充证书 CN。
- 真实的零写 `0`；没有观测、不能确定或分母为零写缺失值。
- 删除了旧契约中的重复 RST 列、伪 segment 均值和无顺序意义的 CN 哈希，换成载荷均值、TLS record 数与 SNI 长度。

## 数据泄漏规则

一条 flow 不能自己决定属于哪个集合。来源清单先为 PCAP/sample/capture/APK 分配 `group_id` 和固定 `split`；所有派生 flow 继承它。训练、LoRA、SupCon-AE、LightGBM 与消融都检查同一 group 不能跨集合。RTD 领域继续预训练默认也只看 train group，避免测试流量提前影响编码器。
