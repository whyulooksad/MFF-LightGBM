# 模型训练说明

## 1. 放置官网数据

- 压缩包：`data/developer/datasets/source/<数据集>/archives/`
- 原样解压：`data/developer/datasets/source/<数据集>/extracted/`
- 不要把 CSV 当成 PCAP，也不要把用户上传放进开发数据。

## 2. 建清单并按来源分组

```powershell
uv run python -m developer.data_prepare.build_manifest `
  --provenance data/developer/datasets/manifests/provenance.json `
  --output data/developer/datasets/manifests/source_manifest.json
uv run python -m developer.data_prepare.split_dataset `
  data/developer/datasets/manifests/source_manifest.json `
  data/developer/datasets/manifests/split_manifest.json `
  --materialize-root data/developer/datasets/prepared
```

`provenance.json` 以 source 下的相对路径为键，填写官网或捕获实验能够确认的 `sample_id`、`capture_id`、`apk_sha256`、`family`、`device`、`capture_batch`、`tool`、`resolver`。如果你根据数据集说明决定多个文件必须整体划分，可直接填写相同的 `group_id`，并用 `group_basis` 说明依据（例如 `apk_sha256`、`capture_batch+resolver`）。显式 `group_id` 优先级最高。没有可靠资料就留空，不能由文件内容猜造。

`split_dataset` 优先按 `sample_id → capture_id → apk_sha256 → PCAP SHA-256` 分组，并在每个“数据集 + 类别”内部按 70/10/20 分配完整来源组。相同 `group_id` 只能属于 train、validation、test 中一个集合；任何一层少于三个独立组会直接报错，需补充数据而不是把同一组拆开。`prepared` 使用同盘硬链接，不复制第二份大 PCAP。

自动识别不了的标签必须先在 source manifest 中人工补成八类之一。不要让程序猜未知标签。

零字节抓包仍保留在 source 和清单中用于追溯，但会标记为 `usable=false`、`exclusion_reason=empty_capture`，不会进入划分、硬链接和训练。

## 3. 运行开发者流水线

```powershell
uv run python -m developer.pipeline --stage flow_features
uv run python -m developer.pipeline --stage preprocess
uv run python -m developer.pipeline --stage pretrain
uv run python -m developer.pipeline --stage lora
uv run python -m developer.pipeline --stage extract
uv run python -m developer.pipeline --stage supcon
uv run python -m developer.pipeline --stage detector
uv run python -m developer.pipeline --stage evaluate
```

也可在数据和显存确认无误后运行 `--stage all`。所有监督训练和消融都强制使用预先写入的 `group_id + split`，缺失、类别覆盖不全或同组跨集合时直接报错，不再随机打散 flow。RTD 只从外层 train 中再按 group 切内部 holdout；LoRA 和 SupCon-AE 用 train 拟合、validation 选最优 checkpoint；SupCon-AE 只训练一次，LightGBM 加载冻结的 reducer。外层 test 只在整条链确定后由 detector/evaluate 做最终报告。

三个 split JSONL 是 manifest 的派生产物，每次运行都会从当前 flow 重建，不会复用旧缓存。缺失值中位数、PCA、SupCon-AE 等所有有学习状态的预处理都只能在 train 上拟合，然后原样变换 validation/test。

## 4. 结果必须重新验证

旧模型使用近似 TLS/X.509 字段和随机 flow 划分，历史成绩只能当历史记录。必须重新执行：

```text
严格 PCAP/TCP/TLS/X.509 提取
→ RTD 领域继续预训练
→ LoRA 八分类
→ 768 维 CLS
→ SupCon-AE 64 维
→ 64 + 80 维融合
→ LightGBM
→ 独立 test
→ fused / semantic-only / manual-only 消融
```

## 5. 发布

候选模型放在 `models/experiments/<run_id>/`。模型包必须带 `manifest.json`、`feature_schema.json` 和 `label_mapping.json`，其中 schema 版本及 80 个字段顺序必须和运行时代码完全相同。

```powershell
uv run python -m developer.release.build_contract models/experiments/<run_id> 2026-09-strict-parser
uv run python -m developer.release.validate_bundle models/experiments/<run_id>
uv run python -m developer.release.publish models/experiments/<run_id> 2026-09-strict-parser --activate
```

发布目录不可覆盖。当前旧模型已归档；新模型通过校验并激活以前，用户检测会明确失败关闭，绝不会把新特征送进旧模型。
